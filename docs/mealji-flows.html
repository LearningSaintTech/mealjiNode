User flow

A customer uses one login. A new Indian mobile number creates the account. An existing number receives the same OTP. Staff and kitchen phones are not turned into customers.

1. Login. POST /api/v1/auth/login with countryCode +91 and the phone. Optional name. Response 201 includes userId. The OTP is not in the body.
2. Verify. POST /api/v1/auth/verify-otp with userId, otp 123456, and x-device-id. A wrong code is 400. Five wrong attempts require a new OTP. Response 201 saves accessToken, refreshToken, and expiresIn.
3. Session. GET /api/v1/auth/me returns the customer, role user, and an empty subscription snapshot. POST /api/v1/auth/refresh rotates the refresh token for the same device. POST /api/v1/auth/logout revokes this device.
4. Location. PUT /api/v1/users/me/location sends latitude and longitude. Google Maps stores the textual address. GET /api/v1/users/me/location reads it back.
5. Service radius. GET /api/v1/users/me/serviceability uses the query coordinates, or the saved location when they are omitted. Only an active kitchen with a map pin can cover the point, and only inside its serviceRadiusKm.

Outside every kitchen

The customer stays signed in. The check returns HTTP 200 with message Not serviceable. data.serviceable is false, data.kitchen is null, and data.distanceKm is null. No kitchen is assigned.

Koramangala is active at 3 km, so a point on that kitchen is Serviceable. Indiranagar is still in setup, so a point there is Not serviceable even though that kitchen has a 3 km radius. A paused kitchen does not cover anyone either.

If no location has been saved and the request has no coordinates, the check returns 400: Set your current location before checking service.

Admin flow

Console accounts use staff login. That request does not create an account. An unknown phone, and a customer phone, return 404.

1. Staff login. POST /api/v1/auth/staff-login with the console phone. Then the same Verify OTP call, otp 123456, and the same x-device-id.
2. Super admin (9000000001) can read people, invite platform staff, change a platform role between super admin and subadmin, and onboard kitchens. They cannot suspend themselves or the last active super admin.
3. Platform subadmin (9000000002) can read people and suspend or activate accounts. They cannot open kitchens, invite staff, or change a super admin account.
4. Invite platform staff. POST /api/v1/admin/staff with a new phone and roleSlug superadmin or subadmin. The phone must not already exist. They later sign in with staff login.
5. Onboard a kitchen. POST /api/v1/admin/kitchens. Send the place, hours, status, and serviceRadiusKm from 0.5 to 25. Google Maps places the address. The contact phone becomes the kitchen admin and signs in with staff login. Pausing a kitchen, or returning it to setup, turns off accepting orders.

Kitchen console

Kitchen admin. GET /api/v1/kitchen/me opens the desk. They can update the place, hours, and service note. Google places the address again when the place changes. Status, the admin phone, and the radius stay with the super admin. They invite kitchen subadmins with POST /api/v1/kitchen/staff.
Orders switch. PATCH /api/v1/kitchen/me/service with acceptingOrders true or false. This works only after a super admin marks the kitchen active. An onboarding kitchen returns 409.
Kitchen subadmin. They can open the desk and use the orders switch when the kitchen is active. They cannot edit the kitchen or manage the team.

Request order in Postman

  1. Import the collection and the local environment. Re-import both after this update so the demo phones and otp 123456 are loaded.
  2. Customer: Login, Verify OTP, Update current location, Check serviceability, Me, Refresh, Logout.
  3. Super admin: set staffPhone to 9000000001, Staff login, Verify OTP, then List users, List kitchens, Onboard kitchen, or Create staff.
  4. Kitchen admin: set staffPhone to 9000000011, Staff login, Verify OTP, then My kitchen, Update service, and List kitchen team.

Login and verify save userId, accessToken, and refreshToken. A kitchen response saves kitchenId.
